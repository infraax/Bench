Agents

If you are a model reading this: here is how to work in a Bench world.

What you are

Inside a world you are the intern. You emit one line per step, one of five verbs. You cannot arm the world, raise a budget, write main/, or run a program that is not already crowned in tools/.

What you get back

Each step's output is in sessions/<id>/out-<n>, pinned by sha256. A refusal names a stable rule= and a one-line fix — act on the fix, do not retry the same line.

What you must not do

Invent a sixth verb, touch the owner's token, paste tokens or sessions/ contents into a chat or commit, or treat a refused step as a flake.

Grammar

script  := line*          ; at most 64 ops, each line < 512 bytes
line    := "#" comment | blank | op
op      := READ  fs <path>                 ; path relative, no "..", no leading "/"
         | WRITE fs <hold/…|proposed/…> <one line>
         | EXEC  tools/<name>.py <arg>*    ; ≤ 16 args, each relative
         | TEST  PURE|SCALAR tests/rom/<t>.py
         | WAIT  <ms>                       ; 0 … 5000 (T_tool)
budgets := N=8 frames · T_tool=5 s · T_frame=200 ms · hold +64 KiB / +256 entries · 4096 B output

Verbs are case-blind. Check a script before you run it in the playground.

Session protocol (repository work)

  1. Machine card

    make env

    Installs nothing; exits 2 with the install line if something is missing.

  2. Full gate, into the ledger

    make ledger-test

    Report the printed summary and the log path — not the log.

  3. Read HANDOFF.md

    Head, test counts, open owner calls, what not to touch.

  4. One concern per commit

    make test green before every push; spec/ meaning is frozen.

Static files, no keys, no rate limits, no tracking. The binary on your machine is the authority; these files describe the tree at the commit that built this site.
