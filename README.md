# Bench

> Bench is a bench, not an assistant. Five intern ops, framed steps, typed evidence, ROM crowns. This repo is the foundation image.

The spec is ROM: [`spec/BENCH_SPEC.md`](spec/BENCH_SPEC.md). If the code and the spec disagree, the code is wrong.
The spec names its sources `harness/*.{py,c,h}`; in this tree they live in `isa/` and `supervisor/`.
Review, plan and tool set: [`DESIGN_REVIEW.md`](DESIGN_REVIEW.md) · [`EVOLUTION.md`](EVOLUTION.md) · [`TOOLBOX.md`](TOOLBOX.md).

## Platform

- **Linux only.** The supervisor uses Linux headers (seccomp, landlock) and `execvpe`. It does not build on macOS.
- Landlock needs kernel ≥ 5.13. Without it, `EXEC` children fail closed (they do not run).
- Python 3.10+ (ROM suite checked on 3.10, 3.11, 3.12, 3.13). stdlib only; pytest used if present.
- C11 compiler, `make`.

## Parts

- `supervisor/` — C. One thread owns the frame: gate, clock, TEST post-conditions, hold quotas,
  delta snapshots, lamps. `sandbox.c` limits tool children; `sha256.c` hashes the board;
  `arm.c` is the one token rule; `mailbox.c` + `helper.c` are the helper mailbox;
  `bus_test.c` checks `woz_bus.h` exhaustively. The ROM crown (`rom_hash.h`) is generated by `make`
  and not committed.
- `isa/` — Python. `hotz_isa.py` (interned, slotted, frozen `Step`; the intern WRITE rule; `hook`),
  `karpathy_rom.py` (`is_ring0`, `midwife`, `install_rom`, `leash`).
- `tools/` — programs reached only via `EXEC`: `hash.py`, `peek.py`, `test_runner.py`.
- `tests/rom/` — Ring 0, pure algebra and truth tables. Every file must pass `is_ring0`.
- `tests/harness/` — driven by `make` (a human, not ROM); may use subprocess to run the binary.
- `main/`, `hold/` — the two address spaces. `sessions/` — snapshots, logs, token, locks.

## Use

```
make test                                 # bus, ring 0, harness — offline, radio unplugged
make e2e                                  # fixture intern -> frames -> snaps -> demo (arms a scratch world)
: > sessions/OWNER_TOKEN                  # arm (owner). make clean keeps it; rm to disarm
./supervisor/bench run [--n N] [--hold-quota BYTES] [--hold-files N] [--keep M] script
./supervisor/bench status [--line]        # the board; --line = one grep-able line
./supervisor/bench kill | demo | snap-ls
./supervisor/bench restore snap-<k> | <session>/snap-<k>
```

Exit codes: 0 ok · 1 fault · 2 usage · 3 killed · 4 ROM changed · 5 not armed / disarmed ·
6 helper missing, silent, lost or wrong version · 7 world busy (or demo already running).

`status --line` example:

```
1790488197-8946 ok n=5/8 snap=005-79f0fe07 lamps=HOLD,BLIND hold=+0/65536 files=+1/256 armed=yes helper=v0 lock=free
```

Status words: `run`, `ok`, `fault`, `halt`, `disarmed`, `restored`, and `crashed` (STATE says `run`
but nobody holds the world lock).

## Session arm (owner token, v0)

`bench run` starts only if the owner armed it: `BENCH_TOKEN` names a token file, or
`sessions/OWNER_TOKEN` exists under the world root (`BENCH_ROOT`, default `.`). A token is valid only if:

- it is a regular file (not a link),
- owned by the uid running bench,
- not group- or world-writable (0600 or 0644 are fine).

Content is not read. At arm, bench pins the token's (dev, ino, mtime). The frame gate re-reads it
before **every** step: removed, replaced by another file, or touched → the next frame does not run,
status `disarmed`, exit 5. The refusal names the rule that failed. `demo` and `status` need no token.

The intern cannot create the token: `WRITE` accepts `hold/` and `proposed/` only, `EXEC` children
are write-limited to the same places, and a `TEST` step that creates or touches it is caught by the
post-conditions below. This stands in for a later hardware key. No key storage, no signature in v0.

## The frame

gate → [TEST: read board] → tool → [TEST: post-conditions] → quotas → snap → inhibit,
all in `frame()` (`supervisor/frame.c`).

- **gate**: KILL, then the pinned token, then helper `FRAME_OK`. A stop here is no step and no snap.
- **TEST post-conditions**: before a `TEST`, the frame hashes `main/` and `tests/rom/` and stats the
  token files; after it, again — whatever the test reported. Anything moved →
  `fault=test-postcondition moved=main,rom,token`, snap without the board (`tree=skipped:tainted`),
  status `disarmed`, exit 5. A touched or minted `sessions/OWNER_TOKEN` is renamed to
  `OWNER_TOKEN.tainted-<session>` (never deleted), so it arms nothing.
- **KILL** reaches a running child at once; the cut step is snapped with `halt op=exec`, status `halt`, exit 3.
- **T_frame** (200 ms) is the C thread's own work: gate, TEST board read, quota walk, snap.
  `T_tool` (5 s) is the child's.
- Budget faults (`T_frame`, `T_session`, over-N) name themselves in the evidence line.
- `WAIT` records what it actually slept (`slept=`).

## Hold quotas

`hold/` may grow per session, against its size at s0, by at most:

| Budget | Default | Per run | Fault |
|---|---|---|---|
| bytes | 64 KiB (`HOLD_QUOTA_BYTES`) | `--hold-quota` > `BENCH_HOLD_QUOTA` | `fault=hold-quota-bytes` |
| entries (files + dirs) | 256 (`HOLD_QUOTA_FILES`) | `--hold-files` > `BENCH_HOLD_FILES` | `fault=hold-quota-files` |

Plain decimal, 0..2^32-1, else exit 2. Checked after every tool (`WRITE` and whatever an `EXEC`'d
tool wrote). Over quota: the step is snapped without the board (`tree=skipped:over-quota`),
status `fault`, exit 1. Both quotas and baselines are frozen in `SESSION`.

The file default (256) is set against `T_frame`: creating ~1000 **new** files in one step costs
~350 ms to snap on the test disk, over the 200 ms budget; 256 new files snap well inside it.
Unchanged files are cheap (see snapshots).

## Snapshots

Every step writes `sessions/<id>/snap-<k>/` with `MANIFEST` (evidence, `tree=` hash of `main/`+`hold/`,
`out=`, `delta=`), `INDEX`, and a copy of `hold/`.

- **By delta**: a file unchanged since the previous board snap — same (ino, size, mtime, ctime) in
  that snap's `INDEX` — is hard-linked from that snap, never from `hold/`. Everything else is copied.
  1000 unchanged files: ~8 ms instead of ~340 ms. A name containing a newline is always copied.
- **Restore**: `bench restore snap-<k>` (owner, armed, world locked). The snap must hold a board and
  `main/` + the snap's `hold/` must hash to its `tree=` before anything moves. The old `hold/` is kept
  in `sessions/<new>/hold.before`. The new session's s0 is the restored board; status `restored`.
- **Retention**: `run` keeps the newest 20 session dirs (`--keep M` > `BENCH_KEEP`). Never pruned:
  `CURRENT`, sessions holding `hold.before`, anything not named `<epoch>-<pid>`. Links not followed.

## Logs and tool output

- `sessions/<id>/log` — supervisor and mailbox lines only (`ARM`, `EXEC … -> out-3`, `MAILBOX …`,
  `RETAIN`, `TAINT`, `RESTORE`).
- `sessions/<id>/out-<n>` — step n's tool stdout+stderr, or the bytes a `READ` returned. The MANIFEST
  pins it: `out=out-<n> bytes=<b> sha256=<hex>`. A tool cannot write a line into the log.

## World lock

`run` and `restore` take a POSIX write lock on `sessions/LOCK` (fcntl, so `F_GETLK` names the holder).
A second one in the same world exits 7 and names the holder's pid. `kill` signals the pid in `PID`
only if that pid holds the lock; a PID file left by a crash is never signalled. `demo` has its own
lock, `sessions/DEMO`, and a knife of `T_tool` × ROM test files; `kill` reaches it too.

## Helper mailbox

`bench run` starts `supervisor/bench-helper` (from `bench`'s own directory) and talks to it over a
unix socket it creates at `sessions/<id>/helper.sock`. This machine only; no intern opcode.

- bench binds, listens and connects **before** the helper starts, then unlinks the path. The helper
  accepts one connection, only from its parent (`SO_PEERCRED`), and closes the listener.
- Three words: `PING`, `ARM_OK`, `FRAME_OK <n>` → `<WORD> yes|no <reason>`. Anything else closes the line.
- bench pins the version: `PING` must answer `helper v0`, else exit 6. Recorded in `SESSION` (`helper=v0`).
- `ARM_OK` at start, `FRAME_OK` before every step. The helper applies the same token rule: it can
  refuse, never arm alone.
- Missing, silent (2 s), garbled or wrong-version helper: exit 6, no `CURRENT`, no frames.

## Tool children (current behavior; `sandbox.c` unchanged)

`is_ring0` is a source check — it stops an accidental network or spawn import in a ROM file,
nothing more. Tool children are limited by the C supervisor:

- **seccomp**, every tool child: network syscalls return `EPERM`; ptrace, mount, namespace and
  key-ring syscalls terminate the child.
- **landlock**, `EXEC` children only: writes allowed under `hold/`, `proposed/`, `tests/proposed/`.
  `TEST` children run without landlock (the test runner needs `/tmp`); the frame's post-conditions
  cover what they must not change.
- **env**: fixed `PATH`, no `LD_PRELOAD` / `PYTHONPATH`; only `LANG`, `LC_*`, `TZ` pass through.
- **ROM crown**: `run`, `demo` and `restore` exit 4 if `tests/rom` no longer matches the hash baked at build.
- **timeout**: each `EXEC`/`TEST` child is killed after `T_tool` (5 s).

Known limit: `execve` stays allowed in tool children. A tool can start other programs; they inherit
the same limits.

Lamps: MAIN and HOLD are never lit together (HOLD wins). BLIND is lit when fb **and** radio are
both pulled — always, in foundation.

## Not in this tree

- **Hardware key / fob** — the token file is the whole v0.
- **Supervisor ops as commands** — `INSTALL_ROM`, `SET_LOOP`, `UNPLUG` exist as `Op` values and are
  refused from the intern; there is no CLI for them. `install_rom()` is a Python function only.
- **Slots beyond fs/tty** — `fb`, `judge`, `radio` are always pulled; `TEST JUDGE` / `TEST VISUAL` are denied.
- **Notch** (Touch / Chunk / Overnight) — only `--n N ≤ 8`; `K`, `T_*` are fixed defaults.
- **`hold/ → main/` merge** — MAIN stays dark. No code sets `LAMP_MAIN`.
- **`wait` on I/O or a gate** — `WAIT` sleeps for time only, at most `T_tool`.
- **Replay** — `OPS` + snaps are written; nothing re-runs them to compare hashes yet.
- Model slot, GUI, network, MCP, multi-agent, skills runtime, Overnight density, macOS build.
