# Bench

> Bench is a bench, not an assistant. Five intern ops, framed steps, typed evidence, ROM crowns. This repo is the foundation image.

The spec is ROM: [`spec/BENCH_SPEC.md`](spec/BENCH_SPEC.md). If the code and the spec disagree, the code is wrong.
The spec names its sources `harness/*.{py,c,h}`; in this tree they live in `isa/` and `supervisor/`.

## Platform

- **Linux only.** The supervisor uses Linux headers (seccomp, landlock) and `execvpe`. It does not build on macOS.
- Landlock needs kernel ≥ 5.13. Without it, `EXEC` children fail closed (they do not run).
- Python 3.10+ (ROM suite checked on 3.10, 3.11, 3.12, 3.13). stdlib only; pytest used if present.
- C11 compiler, `make`.

## Parts

- `supervisor/` — C. One thread owns the frame: gate (KILL, token, helper), clock, hold quota,
  C tree-hash snapshot, lamps. `sandbox.c` limits tool children; `sha256.c` hashes the board;
  `arm.c` is the one token check; `mailbox.c` + `helper.c` are the helper mailbox;
  `bus_test.c` checks `woz_bus.h` exhaustively. The ROM crown (`rom_hash.h`) is generated by `make`
  and not committed.
- `isa/` — Python. `hotz_isa.py` (interned, slotted, frozen `Step`; the intern WRITE rule),
  `karpathy_rom.py` (`is_ring0`, `midwife`, `install_rom`, `leash`).
- `tools/` — programs reached only via `EXEC`: `hash.py`, `peek.py`, `test_runner.py`.
- `tests/rom/` — Ring 0, pure algebra. Every file must pass `is_ring0`.
- `tests/harness/` — driven by `make` (a human, not ROM); may use subprocess to run the binary.
- `main/`, `hold/` — the two address spaces. `sessions/` — snapshots, logs, owner token.

## Session arm (owner token, v0)

`bench run` starts only if the owner armed it. Either:

- `BENCH_TOKEN` names an existing regular file, **or**
- `sessions/OWNER_TOKEN` (a file) exists under the world root (`BENCH_ROOT`, default `.`).

Presence only; the content is not read. Without a token, `run` exits **5** before any session
dir, frame or lamp exists; `status` stays dark. `demo` and `status` need no token.

The token is checked again before **every** frame. Remove it mid-run and the next frame does not
start: status `disarmed`, exit 5. `make clean` keeps `sessions/OWNER_TOKEN`; `rm` it to disarm.

The intern cannot create the token: `WRITE` accepts `hold/` and `proposed/` only
(`intern_may_write` in `isa/hotz_isa.py` mirrors the C rule; ROM and harness tests check they agree),
and `EXEC` children are write-limited to the same places. `TEST` children are not write-limited:
a crowned ROM test could create the token (see `DESIGN_REVIEW.md`, sharp edge 6).
This stands in for a later hardware key. No key storage, no signature, no expiry in v0.

## Helper mailbox

`bench run` starts `supervisor/bench-helper` (from `bench`'s own directory) and talks to it over a
unix socket it creates at `sessions/<id>/helper.sock`. This machine only; no intern opcode.

- bench binds, listens and connects **before** the helper starts, then unlinks the path. The helper
  accepts one connection, only from its parent (`SO_PEERCRED`), and closes the listener.
- Three words, one line each: `PING`, `ARM_OK`, `FRAME_OK <n>` → `<WORD> yes|no <reason>`.
  Anything else closes the line.
- `ARM_OK` at start, `FRAME_OK` in the frame gate before every step. The helper checks the token
  itself: it can refuse, never arm alone.
- Missing, silent (2 s) or garbled helper: exit **6**, no `CURRENT`, no frames; the reason is in
  `sessions/<id>/log`. Every exchange is a `MAILBOX` line in that log.
- The helper gets `BENCH_TOKEN` and nothing else in its environment. It exits on EOF.

## Hold quota

`hold/` may grow by at most the hold quota per session, measured against its size at s0.
Default 64 KiB (`HOLD_QUOTA_BYTES`, `supervisor/frame.h`). Per run:
`--hold-quota BYTES` beats env `BENCH_HOLD_QUOTA` beats the default; plain decimal, 0..2^32-1,
anything else exits 2. `0` means `hold/` may not grow.

Checked after every tool, so it counts both `WRITE` and files an `EXEC`'d tool wrote. Over quota:
the step is snapped with `fault=hold-quota` — manifest and evidence only, the oversized `hold/` is
not hashed or copied (`tree=skipped:over-quota`) — HOLD lamp, status `fault`, exit 1. Later ops do
not run. Quota and baseline are written to `SESSION`.

## The frame

gate → tool → quota → snap → inhibit, all in `frame()` (`supervisor/frame.c`).

- **gate**: KILL, owner token, helper `FRAME_OK`. A stop here is no step and no snap.
- **KILL** reaches a running child at once (it does not wait out `T_tool`); the cut step is snapped
  with `halt op=exec`, then the run stops: status `halt`, exit 3.
- **T_frame** (200 ms) is the C thread's own work: gate + quota walk + snap. `T_tool` (5 s) is the child's.
- Budget faults (`T_frame`, `T_session`, over-N) name themselves in the evidence line.
- `WAIT` records what it actually slept (`slept=`).

## Tool children (current behavior; `sandbox.c` unchanged)

`is_ring0` is a source check — it stops an accidental network or spawn import in a ROM file,
nothing more. Tool children are limited by the C supervisor:

- **seccomp**, every tool child: network syscalls return `EPERM`; ptrace, mount, namespace and
  key-ring syscalls terminate the child.
- **landlock**, `EXEC` children only: writes allowed under `hold/`, `proposed/`, `tests/proposed/`.
  `TEST` children run without landlock (the test runner needs `/tmp`).
- **env**: fixed `PATH`, no `LD_PRELOAD` / `PYTHONPATH`; only `LANG`, `LC_*`, `TZ` pass through.
- **ROM crown**: `bench run` and `bench demo` exit 4 if `tests/rom` no longer matches the hash baked
  at build. Changing ROM is Ring 0: rebuild with `make`.
- **timeout**: each `EXEC`/`TEST` child is killed after `T_tool` (5 s); the `demo` child after 300 s.

Known limit: `execve` stays allowed in tool children (the filter is installed before the tool's
own exec). A tool can start other programs; they inherit the same limits.

## Use

```
make test                               # ring 0 + harness, offline, radio unplugged
make e2e                                # fixture intern -> frames -> snaps -> demo (arms a scratch world)
: > sessions/OWNER_TOKEN                # arm (owner); make clean keeps it, rm to disarm
./supervisor/bench run [--n N] [--hold-quota BYTES] script   # one opcode per frame, N <= 8
./supervisor/bench status | kill | demo | snap-ls
```

Exit codes for `run`: 0 ok · 1 fault · 2 usage · 3 killed · 4 ROM changed · 5 not armed / disarmed ·
6 helper missing, silent or lost.

Lamps: MAIN and HOLD are never lit together (HOLD wins). BLIND is lit when fb **and** radio are
both pulled — always, in foundation.

## Not in this tree

Things the spec or earlier notes describe that are **not** implemented here:

- **Hardware key / fob** — the token file is the whole v0.
- **Resume / Open snap** — snapshots are written (`snap-ls` lists them); nothing loads one back.
- **Supervisor ops as commands** — `INSTALL_ROM`, `SET_LOOP`, `UNPLUG` exist as `Op` values and are
  refused from the intern; there is no CLI for them. `install_rom()` is a Python function only
  (takes `proposed/test_*.py`, never replaces an existing ROM file).
- **Slots beyond fs/tty** — `fb`, `judge`, `radio` are always pulled; `TEST JUDGE` / `TEST VISUAL` are denied.
- **Notch** (Touch / Chunk / Overnight) — only `--n N ≤ 8`; `K`, `T_*` are fixed defaults.
- **`hold/ → main/` merge** — MAIN stays dark. No code sets `LAMP_MAIN`.
- **World lock** — two `bench run` in one world are not excluded.
- **`wait` on I/O or a gate** — `WAIT` sleeps for time only, at most `T_tool`.
- Model slot, GUI, network, MCP, multi-agent, skills runtime, Overnight density, macOS build.
